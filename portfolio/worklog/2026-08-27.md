# 2026-08-27 — Partnership 계정 화면을 실제로 열리게, 소유권·공유·등급까지

**한 줄 요약** · 8/25까지 "만들어 뒀다"고 생각한 Partnership 계정 화면이, 정작 열어 보니 Contacts·Opportunity 탭이 텅 비어 있었다. 원인이 데이터가 아니라 **레코드 페이지가 레코드타입에 활성화되지 않은 것**임을 찾아 화면을 정상화하고, 소유권을 매니저로 이관하고, 공유 규칙·요약 필드·스폰서 등급 자동화·한글화까지 하루에 몰아 정리했다. 하루 종일 마주친 건 **"만들었다"와 "이 사용자 화면에 실제로 뜬다"의 간극**이었다.

---

## 오늘의 목표

8/25에 필드 설계 시안과 더미 100건까지 넣었는데, 데모에서 실제로 열리는 건 화면이다. 오늘은 ① 관리자(매니저)가 PRM을 실제로 소유·조회하도록 **소유권 이관** ② 비어 보이던 **Contacts/Opportunity 탭 연결** ③ "Partnership Activities"라는 정체불명 탭 규명 ④ 리스트뷰·필드·한글 표기 정비까지가 범위였다. 발표에서 매니저 계정으로 로그인해 파트너십 계정을 열었을 때 화면이 자연스러워야 한다.

## 한 것

### 1. Owner 일괄 이관 — Aaron → Lee manager (300건)

내가 적재한 데이터라 소유자가 전부 나(Aaron Choi, `005bm00000UJTQ1AAP`)로 되어 있었다. 데모의 주체는 구단 담당 매니저이므로 **Account 100 / Contact 100 / Opportunity 100 = 총 300건**을 Manager Lee(`005bm00000UowvaAAB`, leemanager@alpaca.com)로 이관했다. 검증: 이관 후 Aaron 소유 3오브젝트 전부 0건, Lee 소유 Account 100건 확인.

### 2. 레코드 페이지가 "비어 보였던" 진짜 이유 (오늘의 핵심)

파트너십 계정을 열면 Details만 있고 Contacts·Opportunity 탭이 안 보였다. 처음엔 공유/데이터 문제로 의심했지만, 근본 원인은 다른 데 있었다 — **"Account - Partner Account" 페이지(`SDO_Sales_Account_Partner_Account`) 자체는 정상인데, Partnership 레코드타입에 이 페이지가 활성화(Activation)돼 있지 않았다.** 그래서 실제로는 Details 탭만 있는 "Account - Default"가 뜨고 있었다.

→ 페이지를 **Partnership 레코드타입에 할당(Activation)** 해서 Contacts/Opportunities 탭이 뜨게 했다. (자세한 건 "막힌 것" 참고.)

### 3. "Partnership Activities" 탭 제거

정체를 파보니 별도 오브젝트가 아니라 **표준 Activity History(`ActivityHistories`)에 라벨만 바꿔 붙인 것**이었다. 실제 담당자 질문에 답하지 않는 탭이라 제거했다 — 데이터 손실 없음(표준 활동 이력은 그대로).

### 4. 탭 구성 재편

최종: `Related → Details → Contacts → Opportunities → Order → Contract → Asset → Success Insights → Account Planning`. Case 탭은 Service Cloud 미사용으로 제거, Quotes·Asset Line Item은 범위 제외.

### 5. Opportunity 가시성 — Public Group + Sharing Rule

Owner를 Lee로 옮겼는데도 Lee가 일부 Opportunity를 못 봤다. Opportunity OWD가 Private이고 Lee manager는 **Role 자체가 없어** 롤 계층 공유가 안 걸렸기 때문이다.

→ **Public Group "Partnership Team"**(멤버 4명: Lee manager, Hyejune Jo, Eunyeong Doh, Rafael Espada) 생성 + **Opportunity Sharing Rule**(그룹 소유 → 그룹에 Read/Write 공유). 적용 후 Lee가 d'Alba 스폰서십 Opportunity 2건(소유자 Eunyeong/Rafael)에 대해 `HasReadAccess/HasEditAccess: true`로 바뀐 것 확인(적용 전 None).

### 6. 리스트뷰 3종 정비

- **파트너 연락처(`Partner Contacts`)** — `filterScope`를 Mine→Everything으로 넓혔더니 팬까지 전체 5,671건이 노출됐다. **RecordType 필터**(`RecordTypeId = '012bm00000BPAnc'`)를 걸어 Partner 타입 106건만 남겼다. 컬럼: `Name | Account Name | Title | Phone | Mobile(신규) | Email | Owner`.
- **파트너십 계정(`Partnership Accounts`)** — 이미 everything 스코프라 스코프 수정 불필요. 컬럼: `Account Name | Industry | Account Owner | Latest Open Opportunity Stage | Amount | Next Step | Days Since Activity`.
- **스폰서 계정(`Sponsor Accounts`)** — 신규 생성(조건 부합 21건). 컬럼: Name / Relationship Type / Phone / Industry / Owner / Partnership Status(→ 이후 Tier 컬럼은 7번에서 교체).

### 7. 스폰서 등급(`Sponsor_Tier__c`) 신설 + 자동 산정

리스트뷰에 등급을 넣으려고 기존 `Tier__c`를 쓰려다, 이 필드가 실은 **Salesforce Maps 전용 필드(A/B/C)**임을 발견했다. 오염을 막기 위해 **`Sponsor_Tier__c`를 신규 생성**(값: Diamond/Platinum/Gold/None — org의 Opportunity `Partner_Tier__c` 값에 맞춤, Silver는 org에 없어 제외)하고, 잘못 넣었던 Maps `Tier__c`의 A/B/C는 **null로 원복**했다.

**Flow 2개(생성·수정 / 삭제)**가 **총 스폰서십 금액 기준으로 등급을 자동 산정**하도록 만들었다 — Diamond(≥15억) 8 / Platinum(5~15억) 6 / Gold(0~5억) 7 / None 0으로 백필. 검증: 계룡건설을 6억으로 올리면 Platinum, 원복하면 Gold로 실시간 재산정 확인.

### 8. Account 요약 필드 3개 + Sync Flow

리스트뷰에 Opportunity 정보를 바로 넣으려다 크로스오브젝트 제약에 막혀("막힌 것" 참고), **Account에 요약 필드**를 두는 쪽으로 우회했다. 신규 필드 `Latest_Open_Opportunity_Stage__c` / `Amount__c` / `Next_Step__c` + System Administrator·Standard User 프로필 FLS 부여. **Flow "Sync Account Latest Open Opportunity"**를 배포·활성화 — Opportunity 생성/수정 시 해당 Account의 "가장 최근 수정된 Open Opportunity" 기준으로 3필드를 자동 동기화하고, 기존 **26개 계정을 백필**했다. (제약: delete 이벤트는 미처리.)

### 9. 관련 리스트를 채우는 샘플 데이터

새로 켠 탭들이 "표시할 항목 없음"조차 안 뜨는 공란이라, 데모용 레코드를 채웠다 — **Contract 78건**(스폰서십 Order가 있는 계정, 최근 Order 기준 12개월·Activated), **AccountPlan 50건**(Partnership Status=Active). 기존 Order 220·Asset 99는 확인만. Details 탭에는 **"연도별 스폰서십 금액" 막대 리포트**(Order 기반 2020~2026, 계정 컨텍스트 자동 필터)를 배포했다.

## 막힌 것

> 이 섹션이 포트폴리오에서 제일 값어치 있다. 문제 → 원인 → 해결 순서로.

### Contacts·Opportunity 탭이 통째로 비어 있다

파트너십 계정을 열면 Details만 있고 Contacts·Opportunity 탭이 없었다.

**원인** · 처음엔 공유/데이터 문제로 접근했지만 아니었다. **레코드 페이지가 Partnership 레코드타입에 활성화(Activation)돼 있지 않아** "Account - Default"가 대신 떴다. 페이지는 멀쩡히 존재했지만 이 레코드타입에 배선되지 않은 것이다.

**해결** · `SDO_Sales_Account_Partner_Account` 페이지를 Partnership 레코드타입에 Activation.

**배운 것** · 8/20·8/24에 이어 또 같은 종류다 — **"컴포넌트가 존재한다"와 "이 레코드타입/사용자 화면에 뜬다"는 다른 문제.** 레코드 페이지도 레코드타입 활성화라는 배선 단계를 통과해야 한다.

### 새로 켠 Order·Contract·Asset·Account Planning 탭이 완전 공란

탭은 생겼는데 "표시할 항목 없음"이라는 안내조차 없이 아무것도 안 떴다.

**원인** · 새 탭들의 `relatedListComponentOverride`를 **NONE**으로 넣었다(정상 탭은 **ADVGRID**). 게다가 **AccountPlan은 Standard User 프로필에 오브젝트 권한 자체가 없었다.**

**해결** · 관련 리스트를 ADVGRID로 재배포 + AccountPlan 오브젝트 권한을 permission set으로 부여.

### Lee manager가 Opportunity를 못 본다

Owner를 Lee로 옮겼는데도 조회가 안 됐다.

**원인** · Opportunity OWD가 Private이고 **Lee manager는 Role이 없어** 롤 계층 공유가 성립하지 않았다.

**해결** · Public Group "Partnership Team" + Opportunity Sharing Rule(그룹→그룹 Read/Write)로 접근 부여.

### 리스트뷰에 Opportunity 컬럼을 못 넣는다

Account 리스트뷰에 Opportunity의 Stage/Amount/Next Step을 넣으려 했다.

```
Could not resolve list view column
```

**원인** · Account↔Opportunity는 1:다라, Account 리스트뷰에서 자식(Opportunity) 필드를 컬럼으로 끌어올 수 없다. Opportunity 리스트뷰에서 2홉 건너 "Account Owner"를 넣는 것도 불가.

**해결** · Account에 요약 필드 3개 + Sync Flow(위 8번)로 값을 Account에 내려 담아 우회. "PRM Opportunity Overview" Opportunity 리스트뷰도 만들어 봤지만 Industry 불가·`LastActivityDate` 전건 공란 문제로 **Report가 더 적합**하다고 결론.

### 중복 커스텀 필드를 지울 수가 없다

`Partner_Certification__c`·`Partner_Program_Level__c`(SDO_ 접두사 필드와 중복, 데모 패키지가 2번 설치된 흔적) 삭제를 시도했다.

```
insufficient access rights on cross-reference id
```

**원인** · 현재 API 실행 계정 권한으로는 이 필드 삭제가 안 된다.

**해결(미완)** · 별도 권한 계정 필요. 미해결로 남김.

### 한글화 범위가 폭발했다

Account/Contact에 비한글 라벨이 150~225개나 됐다.

**원인** · 대부분 **매니지드 패키지 소유** 필드(Maps `SDO_MAPS_`, Field Service `SDO_SFS_`, Pardot `pi__`, Marketing Cloud `et4ae5__` 등)라 수정 자체가 불가. 표준 필드(Industry/Owner/Phone)는 Translation Workbench 영역이다.

**해결** · **PRM에서 실제로 쓰는, 수정 가능한 필드로 범위를 좁혔다.** 표준 필드·패키지 필드는 제외하고 기록으로 남겼다.

**배운 것** · "화면을 한글로"는 무한 작업이 될 수 있다. **우리가 만든 것과 패키지가 준 것을 먼저 가르고, 손댈 수 있는 범위를 확정**한 뒤 들어가야 한다.

### 차트를 탭 우측에 못 붙인다

Details 탭 우측 컬럼에 차트를 두려 했다.

**원인** · 필드 섹션 컬럼은 필드만 허용하고, 탭 본문 2칼럼 배치는 플랫폼 제약. Analytics REST API 파싱도 반복 실패.

**해결** · Details 탭 필드 아래에 스택 배치로 타협하고, 차트는 Analytics REST 대신 **Metadata 배포 방식**으로 전환해 성공.
