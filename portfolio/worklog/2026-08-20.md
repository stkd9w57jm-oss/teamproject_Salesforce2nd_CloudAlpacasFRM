# 2026-08-20 — Partner 전용 화면 계층 구축과 FLS 함정

**한 줄 요약** · 제휴사 레코드가 팬 화면으로 뜨던 문제를 Partner 레코드타입 전용 Layout·Compact Layout·Lightning Record Page를 새로 만들어 분리했다. Fan/Player 설정은 한 줄도 건드리지 않는 것을 원칙으로 잡았다. 중간에 "레이아웃에 넣은 필드가 화면에 안 뜨는" 문제로 오래 막혔는데, 원인이 레이아웃이 아니라 필드 수준 보안(FLS)이었다.

---

## 오늘의 목표

어제 만든 d'Alba Account를 열어보면 **Fan(팬) 화면이 뜬다.** Partner 레코드타입에 Layout·Compact Layout·Lightning Record Page·프로파일 할당이 전부 비어 있어서 기본값을 그대로 상속받고 있었기 때문이다.

데모에서 "제휴사 관리 화면"이라고 열었는데 팬 프로필 항목이 나오면 그 장면 하나로 신뢰를 잃는다. 오늘 목표는 **Partner 레코드타입이 제휴사답게 보이게 만드는 것**, 그리고 어제 못 만든 김하나 Contact를 완성하는 것이었다.

---

## 한 것

### 1. Partner Account 전용 화면 계층

Fan/Player 화면을 건드리지 않는다는 전제 위에서 전부 **신규 생성 후 Partner 레코드타입에만 할당**했다.

| 만든 것 | ID | 구성 |
|---|---|---|
| Page Layout `Partner Account Layout` | `00hbm00000XJoFp` | Account Name / Parent Account / Industry / Type / Partner Type / Website / Description / Phone / Account Owner / Billing Address / Account Record Type |
| Compact Layout `Partner Account Compact Layout` | `0AHbm000005BTmz` | Account Name / Industry / Partner Type / Website / Type / Phone / Account Owner |
| Lightning Record Page `Account - Partner Account` | `0M0bm00000DNF1ZCAX` | 기존 SDO 페이지를 재사용 — **할당 8건** |

Page Layout은 **64개 프로파일 전체에 대해 Partner 레코드타입에만** 할당했다. Master / Account / Business Account 레이아웃은 미변경.

Lightning Record Page 할당 8건의 내역은 이렇다 — Cloud Alpacas FRM·PRM **앱 2종** × Partner **레코드타입** × Standard User·System Administrator **프로파일 2종** × Desktop·Phone **폼팩터 2종**. 기존 `Account - Default`에서 바꿔 달았다. 화면 하나를 바꾸는 데 할당이 8건 필요하다는 걸 이번에 처음 체감했다.

### 2. Partner Contact 전용 레이아웃 + 리스트뷰

| 만든 것 | ID | 비고 |
|---|---|---|
| Page Layout `Partner Contact Layout` | `00hbm00000XKI4E` | Name / Account Name / Title / Department / Email / Phone / Contact Owner / Contact Record Type / Description / Lead Source |
| List View `Partner Contacts` (Contact) | — | 생성만 완료, 필터·컬럼 미정리 |

여기서도 **Player 컬럼(`Player - Contact`)은 미변경**이다. 선수 Contact 4명은 이미 만들어져 있어서, 그쪽 화면이 깨지면 즉시 티가 난다.

담당자 Contact도 만들었다 — **김하나** `003bm00001jBk9xAAC`, RecordType=Partner, Title=Marketing Partnership Manager, Email=hana.kim@dalba.co.kr. 다만 Account 연결은 끝내지 못했다(아래 참고).

### 3. "New Partner Contact" 버튼을 어디에 둘 것인가 — 아직 진행 중

Contact 오브젝트에 Quick Action(`09Dbm00000MtVhdEAF`)으로 만들어뒀는데, 여기서 Salesforce의 제약을 하나 만났다. **Quick Action은 레코드 페이지에만 배치할 수 있고, 리스트뷰의 New 버튼은 대체하지 못한다.** 즉 Partner Contacts 리스트뷰에서 New를 누르면 여전히 기본 동작이 나온다.

**권장안**: 액션을 Contact가 아니라 **Account 오브젝트에 재생성**한다(Target=Contact, RecordType=Partner). Partner Account Layout의 *Salesforce Mobile and Lightning Experience Actions* 영역에 배치하면, **Account 화면에서 담당자를 추가하는 흐름**이 되어 Account가 자동으로 채워진다 — 즉 아래 ③·④에서 겪은 "Account 연결 누락"이 구조적으로 재발하지 않는다.

> 함정 하나 · 그 Actions 영역은 처음엔 드래그가 안 된다. **"override the predefined actions" 링크를 먼저 눌러야** 편집 가능해진다. 이걸 몰라서 한참 헤맸다.

### 4. 판단이 갈렸던 지점 — SDO 데모 레코드를 지울 것인가

Org에는 SDO(Salesforce 데모 패키지) Lead·Opportunity가 각각 50건 넘게 있다. Torp-Price, Tamsco Mfg, Accusage, "Acme - 1,200 Widgets" 같은 것들이라 야구단 데모에 그대로 노출되면 곤란하다.

지우는 게 깔끔해 보이지만 **SDO 패키지 의존성 때문에 삭제는 위험**하다. 그래서 **삭제하지 않고 List View 필터로 격리**하는 방향으로 정했다 — `[SCN-B2B-001]` 코드나 RecordType으로 우리 레코드만 거르면 된다. 되돌릴 수 없는 조치보다 되돌릴 수 있는 조치를 고르는 편이 남은 일정에 맞다.

## 막힌 것

> 이 섹션이 포트폴리오에서 제일 값어치 있다. 문제 → 원인 → 해결 순서로.

### 레이아웃에 분명히 넣은 Account Name이 화면에 아예 안 뜬다

Contact 레이아웃에 Account Name을 배치해 저장했는데, Details 탭에도 Edit 창에도 **필드 자체가 렌더링되지 않았다.** 에러 메시지도 없다. 레이아웃 편집기로 돌아가면 필드는 멀쩡히 그 자리에 있다.

**원인** · 두 겹이었다.

1. 레이아웃 편집기에서 Title을 Account Name **행 위에 드롭**해 덮어써 버렸다. 이건 눈으로 보고 바로 고쳤다.
2. 고친 뒤에도 여전히 안 떴다. 진짜 원인은 **`Contact.AccountId`의 필드 수준 보안(FLS)이 Read-Only**였던 것 — 그래서 라벨만 나오고 입력칸이 없었다.

**해결** · Object Manager → Contact → Fields → Account Name → Set Field-Level Security → Read-Only 해제.

**배운 것** · **"화면에 필드가 안 보인다"는 증상은 레이아웃 문제가 아닐 수 있다.** Salesforce에서 필드가 보이려면 최소 세 겹이 모두 통과해야 한다 — ① 레이아웃에 배치돼 있는가 ② FLS가 열려 있는가 ③ 레코드타입에 그 레이아웃이 할당돼 있는가. 어제의 레코드타입 오류도 결국 같은 종류였다. **"존재한다"와 "이 사용자에게 보인다"는 항상 다른 문제다.** 앞으로 이 증상을 만나면 레이아웃을 다시 열기 전에 FLS부터 확인하는 게 빠르다.

### 김하나 Contact가 아직 d'Alba에 연결되지 않았다 — 유일한 미결

FLS를 해제한 **직후에 세션이 끝나** 값을 입력하지 못했다. 지금 김하나 Contact는 AccountId가 비어 있다.

**원인** · 작업 순서 문제. 막힌 걸 푸는 데 시간을 다 쓰고, 푼 직후 실제 값을 넣는 30초를 남겨두지 않았다.

**해결(미완)** · 김하나 → Edit → Account Name에 "d'Alba" 검색 후 선택 → Save. 30초짜리 작업이다.

**배운 것** · 설정을 고치는 것과 그 설정으로 실제 값을 넣는 것은 다른 단계다. **막힌 걸 풀었으면 그 자리에서 원래 하려던 입력까지 끝내야** 인수인계에 미결이 남지 않는다. 이 항목이 남아 있는 한 은영님의 Opportunity는 담당자 없는 Account에 붙는다.

## 팀에 공유할 것

혼자 정할 수 없는 것, 다른 사람 작업에 영향 가는 것.

1. **@방사라 — Partner 레코드타입에 Layout / Record Page / Compact Layout / 프로파일 할당이 비어 있어 이번에 채웠다.** Fan·Player 관련 설정은 일절 변경하지 않았다.
2. **@전체(결정 필요) — Contact의 Default Record Type을 Player로 유지할지 Partner로 바꿀지.** Lead Convert는 Default를 사용하므로, Player로 두면 제휴사 담당자가 **선수 레코드타입으로 생성된다.** 반대로 Partner로 바꾸면 선수 Contact를 추가할 때 매번 바꿔야 한다. 선수 Contact 4명은 이미 생성이 끝난 상태라 앞으로 만들 Contact는 대부분 제휴사 담당자다 — 이 점을 감안해 결정하면 된다.
3. **@도은영 — 김하나 Contact는 아직 Account 미연결 상태다.** 연결 완료 시 Slack으로 알리겠다. Opportunity를 먼저 걸어도 무방하나, Account Name은 반드시 검색해서 선택할 것.
4. **원격 브라우저에서는 Salesforce Setup의 깊은 화면에 도달하지 못한다**(스크롤 무반응). Setup 작업이 필요한 항목은 처음부터 "사람이 직접 하는 단계"로 분류해 계획에 넣는 게 낫다.
