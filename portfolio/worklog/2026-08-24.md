# 2026-08-24 — FRM과 PRM이 한 Org에서 섞이는 문제, 레코드타입 이름으로 풀다

**한 줄 요약** · 하나의 Org에서 FRM(팬 관리)과 PRM(제휴사 관리)을 같이 운영하다 보니 Account·Contact 탭에 성격이 다른 레코드가 뒤섞여 보였다. Object를 늘리는 대신 **레코드타입 라벨을 업무 언어로 바꾸고 전용 List View를 만드는 것**으로 해결했다. 작업 방식도 이날 바꿨다 — Setup 화면 클릭이 아니라 **Agentforce Vibes IDE에서 메타데이터 XML을 소스로 관리해 배포**하는 Salesforce DX 방식으로 전환했다.

> 📌 **후속** — 이날 만든 `Partnership Accounts` List View는 Partnership Status 컬럼을 `SDO_Partnership_Status__c`로 지정했다. **8/21에 "SDO_ 쪽을 주 필드로 쓴다"고 결정했으므로 그 시점에는 맞는 선택이었다.** 그런데 이후 실제 데이터와 Detail 화면은 접두사 없는 `Partnership_Status__c` 쪽으로 흘러갔고, 그 어긋남이 8/25에 "잠금 아이콘 + 빈칸"으로 터졌다 — [2026-08-25 기록](2026-08-25.md) 참고. 결정이 틀렸다기보다 **결정이 지켜지지 않았고 아무도 그걸 몰랐다.**

---

## 오늘의 목표

Account 탭을 열면 팬(Person Account)과 제휴 기업이 한 목록에 섞여 나오고, Contact 탭을 열면 야구 선수와 제휴사 담당자가 같이 나온다. 같은 Org에서 두 개의 업무를 돌리기 때문에 생긴 문제다.

| App | Account의 의미 | Contact의 의미 |
|---|---|---|
| **FRM** (팬 관계 관리) | Fan (Person Account) | 야구 선수 (Player) |
| **PRM** (제휴 관계 관리) | 파트너십 체결 기업 | 파트너사 담당자 |

여기에 이름 문제가 겹쳐 있었다. Contact의 `Partner` 레코드타입은 Salesforce 기본 PRM 개념 그대로 **"distributor / reseller의 담당자"**로 정의돼 있었다. 우리 업무(스포츠 구단의 스폰서·제휴사 담당자)와 맞지 않는다. Account의 `Partner`도 마찬가지로 **채널 판매 파트너**를 뜻하는 이름이라 스폰서십 업무와 어긋난다.

---

## 한 것

### 1. Object를 늘리지 않고 레코드타입 이름을 바꿨다

가장 먼저 검토한 건 "제휴사용 Custom Object를 따로 만들 것인가"였다. **만들지 않기로 했다.** 파트너 기업은 결국 회사이고 담당자는 사람이라 Account/Contact가 맞는 그릇이다. 문제는 그릇이 아니라 **이름표**였다.

| Object | 기존 Label | 변경 Label | API Name |
|---|---|---|---|
| Account | `Partner` | **`Partnership Account`** | `SDO_Account_Partner` — **유지** |
| Contact | `Partner` | **`Partnership Contact`** | `Partner` — **유지** |
| Contact | `Contact` (범용) | 유지 | — |

**API Name은 건드리지 않은 것이 핵심이다.** 라벨만 바꾸면 화면에 보이는 말은 업무 언어가 되고, 기존 레코드 연결·Flow 참조·리포트 필터는 전부 그대로 산다. 이름을 고치는 작업이 마이그레이션이 되어버리는 걸 피했다.

Contact 레코드타입의 Description도 같이 고쳤다 — `"distributors or resellers"` → `"파트너십 계약을 맺은 회사의 담당자"`. 설명문은 아무도 안 볼 것 같지만, 레코드타입을 고르는 화면에 그대로 뜬다.

### 2. `Partnership Accounts` List View 신규 생성

이름을 바꿔도 목록이 섞이는 건 그대로다. 레코드타입으로 거르는 전용 뷰를 만들었다.

- **필터**: `RecordType.DeveloperName = SDO_Account_Partner`
- **컬럼**: 이름 / Relationship Type(`SDO_Partner_Type__c`) / Partnership Status(`SDO_Partnership_Status__c`) / 전화 / 업종 / 담당자

Partnership Status를 `SDO_` 쪽으로 지정한 건 **8/21에 "`SDO_Partnership_Status__c`를 주 필드로 쓰고, 접두사 없는 쪽은 Page Layout에서 미노출한다"고 정해둔 것을 따른 것**이다. 당시 기준으로는 일관된 선택이었다.

> 🔴 문제는 그 결정이 지켜지지 않았다는 것이다. 실제 데이터와 Detail 화면은 접두사 없는 `Partnership_Status__c`로 흘러갔고, 이 리스트 뷰만 8/21 결정에 남아 있다가 사흘 뒤 통째로 빈칸으로 드러났다. 자세한 건 위 후속 노트 참고.

### 3. 작업 방식을 Salesforce DX로 전환

이날부터 Setup 화면 클릭이 아니라 **Agentforce Vibes IDE에서 메타데이터를 XML 소스로 관리하고 배포**하는 방식으로 바꿨다. 변경한 파일은 이렇게 남는다.

| 파일 경로 | 변경 내용 |
|---|---|
| `force-app/main/default/objects/Account/recordTypes/SDO_Account_Partner.recordType-meta.xml` | label `Partner` → `Partnership Account` |
| `force-app/main/default/objects/Contact/recordTypes/Partner.recordType-meta.xml` | 신규 — label `Partnership Contact`, description 갱신 |
| `force-app/main/default/objects/Account/listViews/PartnershipAccounts.listView-meta.xml` | 신규 — Partnership Account 전용 List View |

**얻은 것** · 무엇이 언제 왜 바뀌었는지가 git 히스토리에 남는다. Setup에서 클릭으로 바꾸면 "누가 언제 뭘 만졌는지"가 사실상 추적되지 않는다.

**대가** · 아래 "막힌 것"에 적었듯, Setup UI가 대신 채워주던 값을 이제 내가 정확히 알아야 한다.

## 막힌 것

> 이 섹션이 포트폴리오에서 제일 값어치 있다. 문제 → 원인 → 해결 순서로.

### List View 컬럼 API 포맷을 몰라 배포를 세 번 실패했다

`listView-meta.xml`에 컬럼을 필드 API 이름으로 적었더니 배포가 계속 거부됐다. 세 번 반복했다.

| 내가 적은 값 | 올바른 값 | 비고 |
|---|---|---|
| `NAME` | `ACCOUNT.NAME` | Account 표준 Name |
| `PHONE` | `ACCOUNT.PHONE1` | 전화 — 이름이 `PHONE1`이다 |
| `WEBSITE` | `ACCOUNT.SITE` | 웹사이트 |
| `OWNER` | `CORE.USERS.ALIAS` | 담당자 — Account가 아니라 User 쪽 경로 |
| `RecordType.DeveloperName` (filter field) | `ACCOUNT.RECORDTYPE` | 레코드타입 필터 |

**원인** · List View 메타데이터의 컬럼은 **필드 API 이름이 아니라 리포트/리스트뷰 전용 컬럼 토큰**을 쓴다. `PHONE1`, `CORE.USERS.ALIAS` 같은 값은 짐작으로는 절대 못 맞힌다.

**해결** · 추측을 그만두고 **Org에 이미 있는 다른 Account List View를 retrieve해서 실제 XML 포맷을 확인**한 뒤 그대로 맞췄다.

**배운 것** · **모르는 포맷은 문서를 찾기 전에 "이미 동작하는 것"을 내려받아 보는 게 빠르다.** Org에는 정답 샘플이 이미 들어 있었다. 그리고 이게 DX 방식으로 옮겨오면서 치른 대가이기도 하다 — Setup 화면에서 컬럼을 고르면 이 토큰들은 UI가 알아서 채워준다. **소스로 관리하는 순간, UI가 감춰주던 내부 표현을 내가 알아야 한다.**

## 팀에 공유할 것

혼자 정할 수 없는 것, 다른 사람 작업에 영향 가는 것.

1. **Account·Contact 레코드타입 라벨이 바뀌었다** — `Partner` → `Partnership Account` / `Partnership Contact`. **API Name은 그대로**라 Flow·리포트·기존 레코드는 영향이 없다. 화면에서 이름이 달라 보이는 것뿐이다.
2. **Object를 늘리지 않기로 했다.** 제휴사는 회사, 담당자는 사람이니 Account/Contact가 맞는 그릇이다. 문제는 그릇이 아니라 이름표였다.
3. **작업 방식이 Salesforce DX로 바뀌었다** — 메타데이터를 `force-app/`에 XML로 두고 배포한다. Setup에서 직접 바꾸면 소스와 Org가 어긋나므로, **같은 컴포넌트를 두 경로로 동시에 건드리지 않도록** 담당 영역을 나눠야 한다.
4. **레코드타입 라벨 변경은 8/21 판단을 뒤집은 것이다.** 8/21에는 *"Label 변경보다 필드로 관계 유형을 구분한다"*고 적었는데, 그 뒤 화면에서 `Partner`라는 말이 계속 채널 판매 파트너로 읽히는 문제가 남아 라벨까지 손봤다. **판단이 바뀐 이력 자체를 기록으로 남긴다.**
