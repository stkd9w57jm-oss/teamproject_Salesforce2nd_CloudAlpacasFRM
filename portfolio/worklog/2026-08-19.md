# 2026-08-19 — Partner Account 생성과 레코드타입 권한 장애

**한 줄 요약** · Phase 2 B2B 파이프라인의 첫 레코드인 제휴사 Account(d'Alba)를 만들어 다음 담당자에게 Record ID를 넘겼다. 이어서 담당자 Contact를 만들려다 레코드타입 권한 오류로 막혔고, 그 원인이 팀 전원에게 영향을 준다는 걸 확인해 프로파일 설정까지 고쳤다. 작업 중 Org를 실측해 "Recommendation 세그먼트가 전부 0명"인 진짜 원인도 찾았다.

---

## 오늘의 목표

Phase 2에서 B2B 파이프라인은 네 사람이 이어 만든다 — 혜준(Lead) → **아론(Account/Contact)** → 은영(Opportunity) → 승우(Product/Quote/Campaign). 내 담당은 Partner Account와 Partner Contact다(`02_TEAM_GUIDE` §11).

은영님이 15:24에 Slack으로 "Opportunity를 걸어야 하니 d'Alba Account를 먼저 만들고 Record ID를 달라"고 요청했다. 김하나 Contact는 "천천히 해도 된다"고 명시했으므로, **오늘의 최소 목표는 Account 1건 + Record ID 전달**이었다.

파생 목표가 하나 더 있었다. Partner 레코드타입이 Fan/Player용 화면 설정을 그대로 쓰고 있어서, 제휴사 레코드를 열면 팬 화면이 뜬다. 이건 화면 작업이라 하루에 다 끝날 일이 아니라 오늘은 문제 범위만 확인했다.

## 한 것

### 1. d'Alba Account 생성 → Record ID 전달

| 항목 | 값 |
|---|---|
| Account | d'Alba(달바) |
| Record ID | `001bm00002hHfcrAAC` |
| RecordType | Partner |
| Industry | Cosmetics / Beauty |
| Type | Prospect |
| Partner Type | Partner |
| Website | https://dalba.co.kr |
| Description | `[SCN-B2B-001]` … Agentforce 추천(Fit 92) → Outbound 선정 |

> 📌 **후속** — 이 레코드는 다음 날(8/20) 폐기했다. Lead Convert를 실제로 검증한 뒤, 아래 2번의 "Choose Existing Account" 전략 대신 **수동 생성분을 지우고 Convert 산출물로 단일화**하는 쪽이 낫다고 판단했기 때문이다. 유효한 Account는 `001bm00002heaKjAAI`다 — [2026-08-20 기록](2026-08-20.md) 참고.

Description에 시나리오 코드 `[SCN-B2B-001]`을 박아둔 건 의도적이다. Org에 SDO(데모 패키지) 레코드가 Lead·Opportunity 각각 50건 넘게 깔려 있어서, **우리가 만든 레코드를 나중에 필터 하나로 골라낼 키**가 필요했다.

### 2. "지금 만들 것인가, Lead Convert를 기다릴 것인가"

이게 오늘 제일 오래 고민한 지점이다.

`P2_DATA_CONTRACT` §3.5는 Account가 **Lead Convert의 결과여야 한다**고 못박고 있다. 그런데 전역 검색에서 "Alba"가 0건 — 혜준님의 Lead가 아직 없었다. 계약대로면 나는 기다려야 하고, 기다리면 은영님 Opportunity도 같이 멈춘다.

**결정: 지금 만들되, Convert 시 "Choose Existing Account"를 쓴다.**

Lead Convert는 새 Account를 만드는 것 말고 **기존 Account를 선택하는 옵션이 있다.** 이걸 쓰면 "Account는 Convert를 거쳐 나온다"는 계약 문장을 깨지 않으면서 병렬로 진행할 수 있다. 문서와 충돌하는 게 아니라, 문서가 허용하는 경로 중 덜 쓰이는 쪽을 고른 것이다.

> ⚠️ 다만 이 결정은 **혜준님에게 전달되지 않으면 그 순간 무너진다.** 안내가 닿지 않으면 Convert 때 "Create New Account"가 눌리고 d'Alba Account가 2개가 된다. 그래서 이건 내 작업이 아니라 팀 공유 항목으로 올렸다(아래 참고).

### 3. Industry picklist에 실제 값 추가

d'Alba는 화장품 회사인데 표준 Industry picklist에 Cosmetics가 없다. 임시로 Retail을 넣어두고 진행한 뒤, Standard Value Set에 **"Cosmetics / Beauty"를 추가하고 값을 교체**했다.

사소해 보이지만 데모에서 Account 화면을 열었을 때 화장품 회사가 "Retail"로 뜨면 심사위원이 바로 본다. 임시값을 남겨두지 않는 게 중요하다고 봤다.

### 4. Org 실측 — 세그먼트가 0명인 진짜 이유

작업하는 김에 Org 현황을 직접 세어봤다. 여기서 오늘 가장 값어치 있는 발견이 나왔다.

| 항목 | 현황 | 판정 |
|---|---|---|
| Fan(Person Account) | 5,024건 | — |
| ├ Current Segment = New Fan | 약 4,200건 (84%) | 🔴 분포 기준 위반 |
| ├ Engagement Level 6종 | 각 750~1,000건 | ✅ 양호 |
| └ Fan Value Tier = VIP | 652건 (약 13%) | ✅ 목표 10~15% 충족 |
| `Admission__c` | 20건 | 🔴 |
| `Engagement_Signal__c` | 3건 | 🔴 |
| 멤버십 보유 / 시즌권 | 1,121건 / 384건 | — |
| Lead / Opportunity | 각 50건+ (전부 SDO 데모) | 🟡 격리 필요 |
| "Alba" 전역 검색 | 0건 | Lead·Opportunity·Campaign 미생성 확인 |
| Recommendation 탭 세그먼트 | **4개 전부 0명** | 🔴 |
| 대시보드 첫 로딩 | 10초 이상 백지 | 🟡 |

팀은 세그먼트가 0명인 원인을 "Admission이 20건뿐이라 그렇다"고 보고 있었다. 그런데 숫자를 나란히 놓고 보니 그게 아니다.

Fan List KPI에 **"신규 팬(7일) = 4.2K"**가 떠 있다. 5,024명 중 4,200명이 최근 7일 안에 가입했다는 뜻 — 사실상 **전원이 8/18에 한꺼번에 적재됐다.** 세그먼트 조건은 "가입 21일 경과", "멤버십 만료 45~75일 전", "최근 30일 관람 감소"처럼 전부 **상대 날짜**를 쓴다. 모두가 어제 가입했으면 이 조건에 걸리는 사람은 구조적으로 0명이다.

**즉 Admission을 아무리 늘려도 안 풀린다.** 반대로 Engagement Level 분포와 Fan Value Tier 분포는 이미 양호하다 — 데이터를 다시 만들 필요는 없고 **날짜만 재배치하면 된다.** 8/14에 세워둔 "CSV에 기준일-N일 수식을 넣어 역산 배치" 원칙이 여기에 그대로 적용된다.

## 막힌 것

> 이 섹션이 포트폴리오에서 제일 값어치 있다. 문제 → 원인 → 해결 순서로.

### Contact를 만들려는데 레코드타입이 유효하지 않다고 한다

```
Record Type ID: this ID value isn't valid for the user: 012bm00000BPAncAAH
```

New Contact 창이 계속 **Player로 고정**됐다. 제휴사 담당자를 만들려는데 선수 레코드타입만 선택 가능한 상태였다.

**원인** · Contact의 Partner 레코드타입이 **System Administrator 프로파일에 할당돼 있지 않았다.** 레코드타입은 "존재하는 것"과 "내가 쓸 수 있는 것"이 다른 문제인데, 이걸 구분하지 못하고 있었다. `P2_B2B_ORG_BASELINE` §3에 이미 `available=false`로 적혀 있었는데, 그 값이 무슨 뜻인지 오류를 보고 나서야 이해했다.

**해결** · Setup → Profiles → System Administrator → Object Settings → Contacts → Edit → Assigned Record Types에서 Partner 체크 후 저장.

**배운 것** · 이 오류의 진짜 무게는 내 Contact 1건이 아니었다. **팀 전원이 같은 프로파일을 쓴다.** 즉 이 상태로 혜준님이 Lead Convert를 돌렸다면 김하나가 **Player 레코드타입 Contact로 생성**됐을 것이다 — 그리고 아무 에러 없이 조용히 그렇게 됐을 것이다. 내 앞에서 에러로 터진 게 차라리 다행이었다. *"내가 막힌 설정이 나만의 문제인지 팀 전체의 문제인지"*를 먼저 확인하는 습관이 필요하다.

### Setup 화면이 스크롤되지 않아 설정에 도달할 수 없다

원격 브라우저 환경에서 Setup 콘텐츠 영역이 **휠·키보드·스크롤바 전부 무반응**이었다. Picklist Value Sets의 Standard Value Sets 표, Profiles의 Object Settings 목록처럼 **아래쪽에 있는 항목에 도달 자체가 불가능**했다.

**원인** · 도구 환경의 한계. Salesforce Setup의 중첩 스크롤 컨테이너를 원격 브라우저가 제어하지 못한다.

**해결** · 해당 단계(Industry 값 추가, 프로파일 레코드타입 할당)만 로컬 브라우저에서 직접 수행했다.

**배운 것** · 다음 세션도 같은 제약이 있다고 봐야 한다. **Setup 깊은 곳의 작업은 "사람이 한다"를 전제로 계획을 짜는 게 맞다.** 자동화로 밀어붙이다 시간을 버리는 것보다, 처음부터 손으로 할 단계를 따로 묶어두는 편이 빠르다.

## 팀에 공유할 것

혼자 정할 수 없는 것, 다른 사람 작업에 영향 가는 것.

1. **@조혜준 — Lead Convert 시 "Create New Account"가 아니라 "Choose Existing Account" → d'Alba(달바)를 선택해야 한다.** 안 하면 Account가 2개 생기고, 은영님 Opportunity가 어느 쪽에 붙었는지 추적이 안 된다. 또한 Contact의 Partner 레코드타입이 프로파일에 미할당 상태였다(방금 해제) — 그 전에 Convert했다면 김하나가 Player 레코드타입으로 생성됐을 것이다.
2. **@도은영 — d'Alba Account `001bm00002hHfcrAAC` 생성 완료.** Opportunity의 Account Name은 반드시 **"d'Alba"를 검색해서 선택**할 것. 직접 타이핑하면 신규 Account가 만들어진다.
3. **@전체 — Recommendation 탭 세그먼트 4개가 0명인 원인은 Admission 건수가 아니다.** 5,024명 전원의 가입일이 8/18에 몰려 있어서 상대 날짜 조건이 전부 불발되는 것이다. Engagement Level·Fan Value Tier 분포는 양호하므로 **데이터를 다시 만들 필요는 없고 날짜만 조정하면 된다.**
4. **@전체 — 날짜 재배치의 오너십이 문서마다 다르다.** `DEMO_DATA_STANDARD` §6.6은 아론, Excel `00_OBJECT_MAP`은 Sara로 되어 있다. 착수 전에 확정이 필요하다.
