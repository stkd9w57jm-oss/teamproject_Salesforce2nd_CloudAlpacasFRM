# 0. 먼저 — 손으로 만들 수 있는 양이 아닙니다

목표 볼륨을 계산하면 **Admission 레코드 약 155건**이 나옵니다.
여기에 Order(굿즈·티켓), Game__c까지 더하면 **250건 이상**입니다.

**Salesforce 화면에서 한 건씩 입력하면 2~3일 걸립니다.** 10 영업일에서 2~3일은 못 씁니다.

### ✅ 유일하게 현실적인 방법 — CSV + Data Import Wizard

**총 1~2시간.** 이 방식이 아니면 이 설계는 실행 불가능하다고 보셔야 합니다.

# 1. B2C — 관람 패턴 데이터

## 1.1 왜 패턴이 필요한가

지금 Org에는 **스냅샷만 있고 시계열이 없습니다.** 이루키의 "3경기 관람"은 숫자 하나일 뿐, **언제 왔는지의 분포**가 없습니다.

분포가 없으면 아래를 **전부** 보여줄 수 없습니다:

| 보여줘야 하는 것 | 필요한 데이터 |
|---|---|
| "최근 30일 관람 감소" (리포트에 이미 있는 카드) | 시계열 방문 기록 |
| At-Risk 전환 — 멘토가 말한 **"안 좋을 때"** | 방문이 끊긴 시점 |
| VIP 후보 감지 (재방문 3회↑) | 반복 방문 |
| `Fan_Activity_Pattern__c` — **Object는 있는데 데이터가 없음** | 패턴 자체 |
| 산리오 제안의 "홈경기당 도달 팬 수" | 경기별 관람 인원 |

## 1.2 선행 조건 — Game__c부터

Admission은 Game__c를 참조합니다. **경기가 없으면 관람 기록을 붙일 수 없습니다.**

| 항목 | 값 |
|---|---|
| Season__c | 2026 시즌 상반기 (기존) |
| Game__c | **홈경기 25건** (2026-03-28 ~ 2026-08-26) |
| Status__c | Played 23건 / Scheduled 2건 |

> Scheduled 2건을 남기는 이유 — `Played_Games__c` Roll-Up이 "전체가 아니라 진행된 경기만" 센다는 걸 화면에서 증명할 수 있습니다.

## 1.3 패턴 유형 — 6가지

기존 팬 22명을 아래로 배분합니다. **팬 수는 늘리지 않습니다.**

| 패턴 | 인원 | 관람 횟수 | 시간 분포 | 데모에서의 역할 |
|---|---|---|---|---|
| **헤비/시즌권** | 2 | 18~22 | 전 기간 고르게 | VIP·충성 팬 근거 |
| **꾸준형** | 4 | 8~12 | 월 2~3회 균등 | "정상" 기준선 |
| **성장형** | 3 | 3→6→9 증가 | 뒤로 갈수록 촘촘 | **이루키 포함** |
| **급감형 (At-Risk)** | 4 | 초반 8회 → 최근 0 | 마지막 방문 **45~70일 전** | ⭐ **"안 좋을 때"의 핵심** |
| **뜨문뜨문형** | 5 | 3~5 | 불규칙, 간격 큼 | 저관여 팬 |
| **휴면형 (Dormant)** | 2 | 2~3 | 전부 **100일+ 전** | 이탈 완료 |
| **신규** | 2 | 0~1 | 최근 가입 | 신규 유입 |
| **합계** | **22** | **약 155건** | | |

### ⭐ 급감형 4명이 이번 설계의 핵심입니다

멘토가 말한 *"안 좋을 때의 pain point를 Salesforce로 해결"*, 그리고 제가 1차 검토에서 지적한 *"세그먼트가 한 방향으로만 움직인다"* — **둘 다 이 4명으로 해결됩니다.**

이 4명이 있어야:
- 리포트의 "최근 30일 관람 감소" 카드에 **실제 숫자가 뜨고**
- Win-back 캠페인 Scene을 **라이브로** 보여줄 수 있고
- "우리 시스템은 나빠지는 신호도 잡는다"가 증명됩니다

## 1.4 🚨 가장 조심할 것 — 날짜 기준

**1차 데모에서 "오늘의 Recommendation = 0"이 뜬 원인이 여기일 가능성이 높습니다.**

대시보드와 리포트에 **상대 날짜 필터**가 걸려 있습니다 — "신규 팬(7일)", "최근 30일 관람 감소". 데이터 날짜가 안 맞으면 **화면이 전부 0으로 뜹니다.**

### 발표일(8/28) 기준 역산 배치

| 구간 | 날짜 범위 | 여기 들어가야 하는 것 |
|---|---|---|
| 최근 7일 | 8/21 ~ 8/28 | **신규 가입 팬 2명** |
| 최근 30일 | 7/29 ~ 8/28 | 헤비·꾸준·성장형의 최근 방문 |
| 30~90일 전 | 5/30 ~ 7/28 | **급감형의 마지막 방문** (여기서 끊김) |
| 90일 이상 전 | ~ 5/29 | 휴면형의 마지막 방문 |

### 2차 데모(8/21)와 최종(8/28)을 둘 다 맞추는 법

7일 차이라 **"최근 30일" 기준은 둘 다 걸립니다.** 문제는 "최근 7일"뿐입니다.

> **실무 팁** — 신규 팬 2명의 가입일만 발표 직전에 손으로 당기세요. **2건이니 1분입니다.**
> 나머지 153건은 손댈 필요 없습니다.

CSV를 만들 때 **날짜를 "기준일로부터 N일 전"으로 계산하는 수식**을 넣어두면, 기준일 셀 하나만 바꿔 전체를 재생성할 수 있습니다. 이 방식을 강력히 권합니다.

## 1.5 굿즈 구매 데이터 — 산리오 제안의 근거

관람 패턴과 별개로, **캐릭터성 굿즈 구매 이력**이 필요합니다. (산리오 제안의 유일한 물증)

| Product2 Category | 구매 팬 수 | 비고 |
|---|---|---|
| Plush (인형) | **6~7명** | 산리오 제안 핵심 근거 |
| Photo Card | **5~6명** | 〃 |
| Uniform | 5명 | 기존 유지 |
| Cheering Item | 4명 | 기존 유지 |

> **중복 허용.** 한 팬이 인형과 포토카드를 다 살 수 있습니다. 오히려 그게 자연스럽습니다.
> 목표: *"캐릭터성 굿즈 구매 이력 보유 팬 **N명**"*이 리포트 한 줄로 나오는 것.

관람 팬 대비 굿즈 구매 전환율이 **현재 73%**입니다. 볼륨을 키운 뒤에도 **65~75% 범위**를 유지하도록 배분하세요 — 이 숫자가 제안서에 들어가므로 크게 흔들리면 안 됩니다.

## 1.6 채널 데이터 — 필드 1개 추가 (예외)

> "Object·필드를 늘리지 않는다" 원칙의 **유일한 예외**로 제안합니다.

멘토 지적: *"Fan App만으로 구매한다는 설정은 비현실적"*

**Order / Admission에 `Data_Source__c` (Picklist) 1개만 추가:**

`Fan App` / `현장 POS` / `티켓 게이트` / `굿즈샵` / `콜센터`

| 비용 | 효과 |
|---|---|
| 필드 1개, CSV 컬럼 1개 | "여러 채널 데이터를 통합한다" 증명 → **Pain Point 1의 답이 크게 강해짐** |

배분 예시: Fan App 40% / 현장 POS 25% / 티켓 게이트 20% / 굿즈샵 10% / 콜센터 5%

**이번 설계에서 투입 대비 효과가 가장 큽니다.**

# 2. B2B — 품목까지 설계

## 2.1 왜 품목이 필요한가

Opportunity에 **품목(OpportunityLineItem)**을 붙이면 **금액이 자동 계산**됩니다. 이게 Sales Cloud의 핵심 동작이고, 멘토가 말한 *"데이터를 가지고 기획 제안까지 가능해야"*에 정확히 답합니다.

> 이전 메모에서 "Quote는 버려라"고 한 것과 충돌하지 않습니다.
> **Quote Object는 여전히 불필요**하고, OpportunityLineItem만으로 견적 효과가 납니다.

## 2.2 Object 구성

| 항목 | 설계 | 비고 |
|---|---|---|
| Account | RecordType = **Partner** | Decision 004로 이미 확정 |
| Contact | RecordType = **Partner Contact** | RecordType만 추가 |
| **Product2** | RecordType = **Sponsorship Item** | 기존 Goods와 분리 |
| PricebookEntry | 품목별 단가 | 표준 Price Book |
| **Opportunity** | Stage 4단계 + 품목 | 핵심 |
| OpportunityLineItem | 표준 | 금액 자동 합산 |

### Product2 추가 필드 (Sponsorship Item용)

| 필드 | 타입 | 용도 |
|---|---|---|
| `Sponsorship_Category__c` | Picklist (노출/굿즈/이벤트/공간) | 품목 분류 |
| `Reach_Basis__c` | Text | **어떤 팬 지표에서 도달 수가 나오는가** |
| `Estimated_Reach__c` | Number | 도달 팬 수 |

### Opportunity 추가 필드

| 필드 | 타입 | 용도 |
|---|---|---|
| `Target_Segment__c` | Picklist/Text | 타깃 팬 세그먼트 |
| `Total_Reach__c` | Roll-Up 또는 Formula | 품목별 도달 수 합계 |

> ⚠️ `Total_Reach__c`를 OpportunityLineItem 기준 Roll-Up Summary로 만들 수 있는지 **승우님 확인 필요**.
> 안 되면 Flow로 계산하거나, 최악의 경우 수기 입력해도 데모에는 지장 없습니다.

## 2.3 스폰서십 품목 7개

> 💰 **금액은 전부 예시입니다.** 정확한 시세를 맞출 필요는 없지만 **자릿수는 현실적이어야** 하므로, 팀에서 한 번 감을 잡아보세요.

| # | 품목 | 분류 | 단가(예시) | 도달 근거 (`Reach_Basis__c`) |
|---|---|---|---|---|
| 1 | 유니폼 슬리브 패치 (시즌) | 노출 | 3.0억 | 전체 홈경기 관람객 누적 |
| 2 | 구장 A보드 광고 (시즌) | 노출 | 1.5억 | 전체 홈경기 관람객 누적 |
| 3 | 콜라보 데이 (홈경기 3회) | 이벤트 | 8,000만 | 경기당 평균 관람 팬 수 |
| 4 | **콜라보 굿즈 — 인형** | 굿즈 | 5,000만 | **Plush 구매 이력 팬 수** |
| 5 | **콜라보 굿즈 — 포토카드** | 굿즈 | 3,000만 | **Photo Card 구매 이력 팬 수** |
| 6 | 콜라보 유니폼 | 굿즈 | 6,000만 | Uniform 구매 이력 팬 수 |
| 7 | 구장 팝업스토어 (2주) | 공간 | 4,000만 | 기간 내 구장 방문 팬 수 |

### ⭐ 이 설계의 핵심

**품목마다 도달 근거가 다르고, 그 근거가 전부 우리 팬 데이터에서 나옵니다.**

4·5·6번이 특히 중요합니다 — **산리오 제안의 실제 무기**이고, §1.5에서 만든 굿즈 구매 데이터와 직접 연결됩니다. 여기서 B2C 데이터와 B2B 제안이 물리적으로 이어집니다.

## 2.4 Opportunity Stage

| Stage | 근거로 쓰는 데이터 |
|---|---|
| 후보 발굴 | 굿즈 카테고리 분석 → 캐릭터 IP 기업 도출 |
| 데이터 기반 제안 | 품목 구성 + 도달 팬 수 합계 |
| 협상 | 이전 콜라보 판매 실적 |
| Closed Won | 계약 (Contract Object 불필요) |

## 2.5 B2B 데이터 볼륨

| Object | 건수 | 내용 |
|---|---|---|
| Account (Partner) | **4** | 산리오 + 후보 3개 (**비교군이 있어야 "골랐다"가 성립**) |
| Contact (Partner) | 4 | 각 사 담당자 1명 |
| Product2 (Sponsorship) | 7 | §2.3 |
| PricebookEntry | 7 | 단가 |
| **Opportunity** | **4** | Stage를 각각 다르게 → **파이프라인이 보여야 Sales로 읽힘** |
| OpportunityLineItem | 10~14 | 산리오 건에 4~5개, 나머지 2~3개씩 |

**총 36~40건.** B2C(약 250건)에 비하면 매우 적습니다. **손으로 만들어도 1~2시간**입니다.

### Opportunity 4건 구성 예시

| 파트너 | Stage | 금액 | 비고 |
|---|---|---|---|
| 캐릭터 IP사 (산리오) | 데이터 기반 제안 | 약 1.7억 | **데모 주인공** |
| 편의점 브랜드 | 협상 | 약 2.4억 | 파이프라인 다양성 |
| 지역 카페 체인 | **Closed Won** | 3,000만 | ⭐ **"이전 콜라보 실적"의 근거** |
| 스포츠 음료 | 후보 발굴 | 약 1.0억 | 초기 단계 |

> 3번(카페, Closed Won)이 중요합니다. 이게 있어야 *"작은 콜라보 성공 → 더 큰 산리오 계약"*이라는 Sales 서사가 **데이터로 성립**합니다. 이 건에는 실제 판매 Order도 몇 건 붙여주세요.

| 3 | **Admission 155건 CSV 생성·적재** | 아론 | 1시간 |
| 4 | Order/OrderItem (굿즈·티켓) CSV | 아론 | 1시간 |

**아론님 합계 약 5시간, 승우님 약 3.5시간.** CSV 방식을 쓴다는 전제입니다.

# 4. 검증 체크리스트

데이터 적재 후 반드시 확인:

- [ ] 리포트 **"최근 30일 관람 감소"**에 숫자가 뜨는가 (급감형 4명이 잡히는가)
- [ ] **"신규 팬(7일)"**에 숫자가 뜨는가
- [ ] **"오늘의 Recommendation"**이 0이 아닌가 ← 1차 데모의 문제
- [ ] 관람 → 굿즈 전환율이 **65~75%** 범위인가
- [ ] `Fan_Activity_Pattern__c`가 갱신되는가 ← **Scene 7(VIP 감지)의 전제**
- [ ] Fan Segment 분포에 At-Risk / Dormant가 **실제로** 나타나는가
- [ ] Opportunity 금액이 품목 합계로 **자동 계산**되는가
- [ ] 이루키의 Segment·Tier·Engagement가 채워졌는가 ← 1차 데모 최우선 결함

# 5. 미결 사항

| 항목 | 필요한 결정 |
|---|---|
| 팬 성별·연령 필드 | 현재 Org에 있는지 미확인. 산리오 제안의 "20~30대 여성" 근거로 **필요할 수 있음** |

> ⚠️ 마지막 항목이 중요합니다. **용어를 정하기 전에 데이터를 넣으면 두 번 일합니다.**
