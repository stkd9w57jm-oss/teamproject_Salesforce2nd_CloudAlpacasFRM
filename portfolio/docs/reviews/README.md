## 2. 오늘 발견된 것 — 1차 Demo의 결함

실제 Org(`trailsignup-2abe91721f6a94`) 화면을 직접 클릭해 확인했다. 상세는 `01_demo-review.md`.

### 🔴 치명적

**이루키 레코드가 자기모순 상태다.** 같은 팬이 세 화면에서 다르게 나온다.

| 화면 | 값 |
|---|---|
| Fan Profile 상단 | Current Segment = **New Fan**, Fan Value Tier = **빈칸**, Engagement Level = **빈칸** |
| Summary 탭 | 3경기 관람, 멤버십 **Active**, LTV **₩124,000**, 팬 건강도 **0** |
| 세그먼트 기회 화면 | **"멤버십 전환 완료 팬 · 성공 여정 완료"** 대표 팬 |

Core Scene 4개 중 3개가 이 화면을 쓴다. 특히 Scene 4의 *"경기장에 온 순간 Active Fan으로 자동 전환됩니다"*를 **라이브로 보여줄 수 없다.**

### 🔴 김매니저의 업무 동선이 끊긴다

"세그먼트 기회" 화면은 *"다음 행동을 결정하세요"*라고 안내하지만 — `대상 팬 보기`는 **무반응**이고, Fan 360 패널에 **조치 버튼이 없다**. 조치 버튼(`조치 완료 처리`)은 Fan 레코드의 Recommended Actions 탭에 따로 있다.
**기능은 다 있는데 두 화면이 연결되어 있지 않을 뿐이다.**

### 🟡 발표 전 정리 (15분~1시간)

- Fan List **맨 첫 줄에 "Debug Welcome Fan"** 테스트 레코드
- 대시보드 하단 캠페인 목록이 **Salesforce Demo Org 기본 샘플** ("Annual Customer Conference, 100k sent" 등)
- "오늘의 Recommendation = 0" vs 실제 세그먼트 기회 4개 → 불일치
- 대시보드 갱신 시각이 하루 전 → 발표 직전 Refresh 필수

### 🟡 숫자 체계 충돌

같은 페이지에 **"전체 팬 20명"과 "대상 팬 677명"**이 나란히 있다. Recommendation 화면은 또 3,842 / 1,204 / 2,130.
→ **실제 데이터 쪽으로 통일 권장.** 비율(73%)로 말하면 규모가 작아도 설득력이 유지된다.

### 🟡 "세그먼트" 명칭 혼선 — 필드는 3개, 화면은 전부 "세그먼트"

| 필드 | 축 | 값 |
|---|---|---|
| `Current_Segment__c` | 생애주기 | New / Active / At-Risk / Dormant / Unreachable Fan |
| `Engagement_Level__c` | 참여도 | 가입 / 활동 / 관심 / 충성 / 핵심 / 멤버십 팬 |
| `Fan_Value_Tier__c` | 가치 등급 | 일반 / 우수 / VIP |

세 축을 나눈 것 자체는 좋은 설계다. **문제는 화면이 구분해 주지 않는 것이다.**

- 리포트 "**팬 세그먼트 구성**" → 실제로는 **Engagement Level**
- "**Segment별 전환율**" → VIP는 Fan Value Tier, 나머지는 Engagement Level — **두 필드가 섞였다**
- FRM 대시보드 "Fan Segment 분포"만 실제 `Current_Segment__c`

> **원인 추정** — 이 Org은 Salesforce Demo Org 기반이라 Account에 이름에 "Segment"가 들어간 필드가 **5개**다
> (`Current_Segment__c`, `Segment_Updated_Date__c`, `SDO_MAPS_Segment_c__c`, `SDO_SPM_Segment_Auto_Calc__c`, `SDO_SPM_Segment_Formatted__c`).
> 리포트 작성 시 다른 필드를 집었을 가능성이 있다.

**해결: 필드를 합치지 말고 화면 제목만 정확히 단다.** 라벨 수정이므로 반나절. 데이터는 건드리지 않는다.

## 3. 산리오 — 왜 이 제휴가 성립하는가

상세는 `03_sanrio-research.md`.

| 항목 | 내용 |
|---|---|
| FY2026 실적 | 매출 1,940억 엔 **+33.9%**, 영업이익 793억 엔 **+48.4%** — 사상 최고 |
| 성장 동력 | 헬로키티 비중 **35%**, 나머지 65%를 다른 캐릭터가 담당 |
| 협상 카드 | 산리오의 과제는 "헬로키티 외 캐릭터 노출 채널" → **선수별 캐릭터 매칭** 제안 |
| ⭐ 레퍼런스 | **에버랜드** 산리오 콜라보 기간 방문객 **전년比 약 10% 증가**, 만족도 역대 최고 |
| 스포츠 실적 | MLB 30개 구단 / **K리그 2026 진행 중** / Team USA |
| 우리의 공백 | 확인된 범위에서 **KBO 구단 사례 없음** |

> 제안서 첫 문장: *"산리오는 미국 야구와 한국 축구에서 이미 성공했습니다. 남은 건 한국 야구입니다."*
> 여기에 우리 실측치 **"경기장에 온 팬의 73%가 굿즈를 구매한다"**를 붙인다.

⚠️ 데스크 리서치의 한계 — 발표 전 KBO 구단 사례를 재확인할 것.
⚠️ 발표에서는 "산리오 같은 캐릭터 IP 기업" 또는 가상 브랜드명 권장. 내부 문서는 산리오 유지.

## 4. 데이터 방침

상세는 `04_data-design.md`.

- **볼륨**: 실제 구장처럼 방문 건수를 만 단위로. Data Storage는 52.2GB 중 0% 사용이라 **용량 제약 없음**
- 🔴 **적재 전 Record-Triggered Flow를 반드시 비활성화**할 것. 몇 만 건 적재 시 Flow가 몇 만 번 돌아 실패하거나 Org이 마비된다
- Data Import Wizard는 **5만 건 제한** → 초과 시 **Data Loader**
- **작게 테스트 → 검증 → 전량 적재** 순서. 재적재·삭제 비용이 크다
- 🚨 **날짜 기준**: 대시보드에 상대 날짜 필터("신규 팬 7일", "최근 30일 관람 감소")가 있어
  데이터 날짜가 안 맞으면 **아무리 많이 넣어도 화면이 0으로 뜬다.** 발표일 기준 역산 배치 필수
- **패턴 유형 6가지**(헤비 / 꾸준 / 성장 / **급감(At-Risk)** / 뜨문뜨문 / 휴면)로 방문 이력을 구성.
  **급감형이 핵심** — 멘토 피드백 *"안 좋을 때의 pain point"*와 *"세그먼트가 한 방향으로만 움직인다"*를 동시에 해결

| 필드 | 타입 | 왜 필요한가 | 판단 |
|---|---|---|---|
| `Target_Segment__c` | Picklist | 타깃 팬 세그먼트 | ⬜ |

| ⭐ **`Minimum_Guarantee__c`** | Currency | **최소보증금(MG)** — 캐릭터 라이선싱 계약의 핵심 구조 | ⬜ |

> 라이선싱 계약은 *"최소보증금을 선지급하고 실제 판매액의 X%를 로열티로 내되, MG를 넘으면 차액 정산"* 구조다.
> 그리고 **MG를 얼마로 정할지가 곧 예상 판매량이고, 예상 판매량은 우리 팬 데이터에서 나온다:**
>
> *"굿즈 구매 이력 팬 N명 × 전환율 73% × 객단가 → **MG 5,000만원은 저희 데이터상 회수 가능합니다.**"*
>
> 이 한 문장이 B2C 데이터와 B2B 계약을 숫자로 잇는다.

## 7. 참고 — 멘토 피드백의 관통선

여러 갈래로 들리지만 하나다: **"보여주기에서 실행하기로 가라."**

- *"대시보드는 이제 당연해져서 성장세가 꺾였다"*
- *"캠페인 액션이 더 깊어져야 한다"*
- *"영업사원이 결정 단계에 있을 수 있게"*
- *"팀원이 어디에 시간을 제일 많이 쓰는지가 핵심"*

이는 1차 검토에서 지적된 *"Recommendation이 생성만 되고 실행이 없다"*와 **같은 문제**다.

**실무적 함의**: 발표에서 **대시보드 보여주는 시간을 줄이고, 액션 실행을 보여주는 시간을 늘린다.**

### 페르소나 — 3명이 될 뻔했으나 2명으로 정리

멘토의 *"영업사원이 결정 단계에 있을 수 있게"*가 곧 **팀원 관점**이다.
박대리(제휴 영업)가 *"기록 업무가 늘어나는 팀원"*이자 *"결정 단계에 있어야 하는 영업사원"* — **한 사람이다.**

| | 김매니저 (매니저) | 박대리 (팀원·영업) |
|---|---|---|
| CRM이 주는 것 | 데이터가 취합되어 잘 보임 | **입력 업무만 늘어남** ← 핵심 |
| 시간을 가장 많이 쓰는 일 | — | 제안서용 자료 취합 (엑셀 재작업) |
| 가장 어려운 일 | — | 어느 기업에 어떤 근거로 접근할지 판단 |
| 도와주면 효과적인 것 | — | 팬 데이터 → **제안 초안 자동 생성** |

멘토가 강조한 *"CRM은 매니저뿐 아니라 팀원에게도 도움이 되어야 한다(매우매우 중요)"*가
**페르소나를 늘리지 않고** B2B 스토리 안에서 해결된다.
